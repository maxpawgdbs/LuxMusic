# Проверка 0.7.1 без Docker

Дата: 6–7 сентября 2026 года. Windows, JDK 21.0.10, Android SDK 36, Gradle 9.3.1; отдельный Android-эмулятор `LuxMusicTest`. Из-за пути с кириллицей сборка выполнялась в ASCII-копии репозитория. Docker не использовался ни локально, ни в Android CI.

## Автоматические проверки

- `testDebugUnitTest`: **144 теста, 0 ошибок/падений**.
- `assembleDebug assembleDebugAndroidTest -Pluxmusic.emulator=true`: успешно.
- AndroidJUnitRunner: **20 обязательных тестов прошли**, 1 необязательный сетевой тест пропущен без URL; итог runner — `OK (21 tests)`, 24.744 с.
- `lintRelease assembleRelease`: успешно, в том числе R8 и `verifyReleaseRuntimeKeepRules`. Lint: **0 ошибок, 26 предупреждений** — главным образом обновления зависимостей, стилевые рекомендации и существующие предупреждения манифеста/ресурсов.
- Новое покрытие: домены/алиасы и маршрутизация площадок; декларация подбора и отложенных каталогов; отсутствие лишних метаданных; резерв TikTok до обновления; однократное обновление при известных ошибках; прямые файлы, редиректы, HTML, обрывы, размер, отмена, имена; превью; публичные метаданные; системный HTTP-прокси; реальные параметры нативного запроса и игнорирование старых cookies YouTube.

Тесты с локальным HTTP-сервером запускались без системного прокси. Если прокси включён, настройте исключения для loopback либо отключите его на **тестовом** эмуляторе: иначе localhost-запрос уходит на сервер прокси, а не к тестовой фикстуре. Для живых проверок использовался отдельно настроенный системный HTTP-прокси. Его адрес в приложение не включён.

## Живые загрузки

На компьютере использован именно bundled yt-dlp **2026.08.19**, Python 3.13, Node и FFmpeg 8.1.2, без cookies и аккаунтов. Проверялся реальный аудиофайл через ffprobe. Компьютер использовал свой настроенный HTTP-прокси. В Android — встроенные Python, QuickJS, FFmpeg, реальный `LinkDownloader`, проверка длительности и импорт в библиотеку; новые тестовые треки удалялись после проверки.

Время включает извлечение и прочие операции; на компьютере несколько процессов шли параллельно, на Android отличаются runtime, окружение и начало отсчёта. Это **не сопоставимый бенчмарк с 0.7** и не основание обещать конкретный множитель ускорения.

YouTube сначала завершался TLS-тайм-аутом при прямом выходе в сеть. В ходе проверки исправлено игнорирование системного HTTP-прокси нативным Python; после этого реальная Android-загрузка прошла. Проверка сертификатов не отключалась, режим обхода входа/подписки не добавлялся.

Итого: семь источников подтверждены на Android — YouTube, TikTok, Bandcamp, SoundCloud, JioSaavn, RuTube и VK Видео — плюс прямой файл. Jamendo подтверждён только на компьютере; Android-проверка не прошла, несмотря на успешные метаданные в повторном тесте компьютера.

Instagram не подтверждён: у двух публикаций не получен аудиоформат, ещё одна вернула ошибку TLS. Audiomack: текущий экстрактор получил HTTP 404 от старого API. Яндекс Видео: сетевая ошибка старого тестового stream_id. Эти три площадки обозначены экспериментальными и в интерфейсе. Публичный API метаданных Deezer и страница Spotify доступны; это не проверка оригинального скачивания из платных/закрытых каталогов. Остальные режимы подбора не объявляются подтверждёнными сквозными загрузками.

## Библиотека и подпись

Обновление установленного официального **0.7 (versionCode 7000041)** до локального подписанного release **0.7.1 (7001000)** выполнялось через `adb install -r`, без удаления приложения или очистки данных. Java/platform runner проверил неизменность байтов существующего аудио, пути и ID, названия и состава плейлиста.

Для сохранённой очереди на паузе и очереди с отсутствующим файлом выполнены отдельные холодные запуски. Через 16 секунд процесс оставался тем же, библиотека показывала `Upgrade test`. Это проверяет в том числе отложенный foreground-service timeout из 0.7.
